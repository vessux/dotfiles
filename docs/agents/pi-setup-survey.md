# Pi setup survey (inspiration pass)

A capture of pi-coding-agent setup patterns surveyed from the upstream
`earendil-works/pi-mono` dogfood config, the `badlogic/pi-skills` ecosystem, the
`anthropics/skills` collection, and pi's own docs — mapped against **this repo's
current pi setup**. This is a menu, not a decision record. Pick items one at a
time; when something is actually adopted, cut a bead (`bd create`) and, where it
changes a posture durably, an ADR.

It was produced twice and the second pass corrected three reads from the first;
the corrections are kept inline so a future reader isn't misled.

## What is in the repo now (verified at survey time)

- `pi/agent/settings.json` — `defaultProvider: nvidia`, `defaultModel:
  nvidia/nemotron-3-ultra-550b-a55b`, `defaultThinkingLevel: high`, `npmCommand`
  via mise (`["mise","exec","node@24","--","npm"]`), `enabledModels` 6-entry
  cycle, `packages: ["npm:pi-claude-shimmer"]`, `extensions: []`, analytics off.
- Auto-active extensions:
  - `pi-claude-shimmer` (npm package) — renders pi's built-in working indicator
    via `ctx.ui.setWorkingIndicator(...)`; notifies on `turn_end`.
  - `notify-publisher` (auto-discovered at `pi/agent/extensions/notify-publisher/`)
    — POSTs `"Pi: <project> ready"` to the ntfy.sh topic Claude Code shares.
  - Both load via **auto-discovery**, not the `extensions` array. The `extensions`
    array only adds *explicit extra* paths; empty `extensions` does **not** disable
    auto-discovered or package extensions. To turn one off, remove the dir/package.
- Manual-only extension:
  - `turn-timer` at `pi/extensions/turn-timer.ts` — **double-orphaned**: it lives
    outside the `pi/agent/extensions/` auto-discover tree **and** is not in
    `settings.extensions`, so it loads only via `pi --extension <path>`.
- `pi/agent/{skills,prompts,themes}/` and `keybindings.json`,
  `AGENTS.md/SYSTEM.md/APPEND_SYSTEM.md` — all empty or absent, but the
  `.gitignore` whitelist already tracks them.
- `pi/agent/models.json` — regenerated by `bin/pi-sync-nvidia-models`
  (gitignored).
- Nix env (`nix/flake.nix`): `PI_CODING_AGENT_DIR=~/.config/pi/agent`,
  `PI_CODING_AGENT_SESSION_DIR=~/.local/share/pi/sessions`,
  `PI_SKIP_VERSION_CHECK=1`.
- tmux `extended-keys csi-u` set (required for Pi's modified-Enter keys).
- `README.md` documents a Gondolin setup, but **Gondolin is not tracked** in the
  repo at survey time — treat it as planned, not present.

## Corrections carried from the second review pass

1. **`turn-timer` and `pi-claude-shimmer` overlap — it is redundancy, not a
   collision.** Shimmer drives the working-indicator line; turn-timer draws a
   *separate* `ctx.ui.setStatus("turn-timer", …)` footer slot. They don't fight
   for the same slot, but they **duplicate information** (elapsed time + spinner +
   completion verb) and both fire a `turn_end` notify — running both means two
   visible spinners and two completion toasts. Shimmer is the strict superset
   (tokens, stall detection, thinking glow, tool-use flash). turn-timer's only
   unique bits are the pastel rainbow and a cosmetic mini-progress-bar.
   **Reframing:** turn-timer is a retirement or relocation candidate, not a
   "keep alongside shimmer."
2. **`notify-publisher`/shimmer load via auto-discovery**, not `extensions: []`
   (see above).
3. **Gondolin is documented but not tracked** — affects how `plan-mode`/`sandbox`
   are framed: they are not "complements to your existing Gondolin," they are the
   practical light-isolation tier *until* Gondolin is actually built.

## Prompt Templates — adopt from `badlogic/pi-mono` dogfood

Project-level `.pi/prompts/*.md`, declarative only. Most relevant:

- **`/wr` → `/deliver`** — context-aware wrap (changelog + commit + push),
  `[instructions]` arg. Mirrors this repo's `clerk`/`nextdelivery`/
  `dotfiles-dft.N` gate as one command. Highest fit.
- **`/pr <PR-URL>`** — review a PR by URL without checking out (files-only via
  `gh pr diff` + `git show <ref>:<path>`). Matches the no-`gh pr checkout`
  discipline pi-mono's own `AGENTS.md` enforces.
- **`/cl`** — changelog audit since last release tag. Pairs with the delivery
  gate's changelog expectation.
- **`/is <issue>`**, **`/sa <advisory>`** — GitHub-issue and security-advisory
  flows; only if GitHub/HF engagement matters.
- Adopt `argument-hint:` frontmatter uniformly — makes `/` autocomplete show
  `<PR-URL>` etc.

## Skills — point pi at existing Umbel skills, plus curated upstream

Biggest no-code win: pi loads Claude-Code skill dirs directly:
```json
{ "skills": ["~/.config/umbel/skills"] }
```
This brings the umbel `local/` skills into Pi sessions with one line:
`karpathy-guidelines` (surgical-edit guardrails), `glean` (end-of-session
impediment harvest), `presort` (beads inbox triage), `borklog` (project memory
scaffolder), `cc-cost` (session cost report).

Curated upstream (cross-harness; install via `packages` or clone into
`pi/agent/skills/<name>/`):

| Skill | Fit | Note |
|---|---|---|
| brave-search | High | Gives the agent web search (no browser); free Brave tier. |
| transcribe | Medium | Local Whisper on Apple Silicon; voice → session context. |
| browser-tools | Medium | CDP automation; only if dogfooding `plannotator` SVG live. |
| youtube-transcript | Low-med | Learns from talks. |
| vscode / gccli / gdcli / gmcli | Low | Depends on personal-productivity surface. |

anthropics/skills (Apache) includes **`skill-creator`** — teaches the agent to
write well-formed skills, natural companion to an `umbel/skills/local/write-a-skill`
pattern.

Object-form package filtering keeps a package but loads only chosen skills:
```json
{ "packages": [{ "source": "pi-skills", "skills": ["brave-search","transcribe"] }] }
```

## Extensions — priority order (given the shimmer correction)

1. **`tps.ts`** — copy verbatim from pi-mono `.pi/extensions/tps.ts`. `agent_end`
   notify of tok/s + per-bucket token totals. Sharper rationale now: with a
   6-model NVIDIA cycle, tps *measures* which model is cheapest/fastest per
   task. ~30 lines.
2. **Subagent** (official example) — port umbel `superpowers/subagent-driven-
   development` personas to `~/.pi/agent/agents/*.md`. Single/parallel/chain;
   isolated context per subprocess; per-agent usage render. Highest leverage for
   non-trivial sessions on cheaper NVIDIA models — keeps orchestrator context
   clean.
3. **Plan-mode** (official) — `/plan` read-only toggle, bash allowlist (the
   `DESTRUCTIVE_PATTERNS` regex is a ready reference), step-extraction widget.
   Now the practical "let it look, don't let it touch" tier given Gondolin isn't
   built.
4. **Sandbox** (official, macOS `sandbox-exec`) — host-native FS/network
   allowlist (`allowWrite:[".","/tmp"]`, `denyRead:["~/.ssh","~/.aws"]`,
   `denyWrite:[".env"]`, `allowedDomains:["github.com","*.github.com"]`). No
   QEMU cost; coexists with a future Gondolin as the fast-trust tier.
5. **`prompt-url-widget.ts`** (pi-mono) — if `/pr` + `/is` are adopted, fetches
   PR/issue/advisory metadata and renders a persistent `DynamicBorder` widget via
   `ctx.ui.custom()`. Demonstrates the custom-TUI-component surface not yet
   used here.
6. **`import-repro` (`/ir`)** (pi-mono) — pull a shared session
   (gist / `pi.dev/session/#<id>` / issue URL) and resume locally. Only if
   consuming published sessions.
7. **Tiny destructive-bash `tool_call` guard** — ~15-line `tool_call`
   interception that `ctx.ui.confirm`s `rm -rf`/`sudo`. Claude-Code's `auto`-
   permission-adjacent safety on Pi.
8. **Decide turn-timer's fate** — retire it (shimmer supersedes), or move it
   under `pi/agent/extensions/turn-timer/index.ts` and drop shimmer. Don't leave
   it double-orphaned.

## Theme — Catppuccin JSON

`pi/agent/themes/catppuccin-mocha.json` (gitignore-whitelisted). Unifies Pi with
the Ghostty/Starship/tmux/yazi Catppuccin palette. Low effort, daily payoff.

## Keybindings — `pi/agent/keybindings.json`

Defaults only. Most relevant *unbound* actions (all default `(none)`):
`app.session.new`, `app.session.tree`, `app.session.fork`, `app.session.resume`.
Binding `/tree` to a key is the move if subagents are adopted — tree/fork/branch-
summary is Pi's standout vs Claude Code and would see heavy use in a multi-agent
flow. Note collisions: `app.thinking.toggle` is `ctrl+t`; `app.session.togglePath`
is `ctrl+p` (also model cycle). Emacs editor bindings only if muscle memory asks.

## Settings knobs (no new files)

| Setting | Note |
|---|---|
| `compaction.keepRecentTokens` (20000 → ~14000) | `thinkingLevel: high` + NVIDIA `supportsLongCacheRetention:false` → compact sooner, cheaper long sessions. |
| `retry.provider.timeoutMs` → `3600000` | Long `high`-thinking turns on free NVIDIA endpoints; prevent premature timeout. |
| `shellCommandPrefix` → `"shopt -s expand_aliases\neval \"$(grep '^alias ' ~/.zshrc)\""` | **Big.** Pi runs `bash -c`; zsh aliases don't load. Note most heavy lifers are already `bin/` executables (ADR 0001), so this only re-enables *remaining* zsh aliases inside agent Bash. |
| `quietStartup: true` | notify-publisher already covers "ready"; quieter tmux pane. |
| `doubleEscapeAction` → `"fork"` | Abort a bad turn → fork-and-retry variant. Personal. |
| `treeFilterMode` → `"no-tools"` | Declutters the tree you'd navigate more with subagents. |
| `thinkingBudgets` | Pin per-level budgets so `high` isn't unbounded on a free endpoint. |

## System prompt files — highest-leverage doc change

`pi/agent/APPEND_SYSTEM.md` (whitelisted, absent). A compact global posture —
"macOS, NVIDIA models, surgical edits, verify with tests, commit only when asked,
use beads not GitHub issues, ntfy notifications" — gives every Pi session the base
posture without per-project repetition. Model it on pi-mono's own `AGENTS.md`
(crisp, ~60 lines: conversational style + code quality + git rules + commands).
