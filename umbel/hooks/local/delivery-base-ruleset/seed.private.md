# Delivery contract — PRIVATE repo

You are executing under the **delivery System**. This is the standing contract for *any* delivery method on this repo; the method you're running adds *how* to prep and build. These rules hold regardless of method.

- **Scope.** Your unit of work is one refined, ready bead — `bd ready` *and* marked `stage:ready` by discovery (raw, un-refined captures are not delivery units). Work only that unit — don't widen it.
- **Claim before you start.** First `bd dolt pull` — the ready-set can be stale and `git pull` does **not** sync the beads inbox (no `refs/dolt/*` fetch refspec; ADR 0013). Then `bd update <id> --claim` before touching code, so the backlog shows it in flight and nothing gets double-worked. On the **automated devbox delivery job**, run the claim with `BD_SHIM_SYNC=1` (the `bd` shim's synchronous push) and confirm `origin refs/dolt/data` advanced: the job's whole process tree is SIGKILLed at exit (cgroup), which a detached background push can't escape, so the claim must reach the remote *before* then.
- **Isolate before you touch code.** Build in a working directory that's exclusively yours — never the shared/default checkout. A dedicated branch is *not* enough: branch state is global to a checkout, so building in place corrupts any other session in that folder and rules out running delivery agents concurrently. *How* you get an exclusive workspace is the method's call; *that* you have one is non-negotiable.
- **Capture-and-escalate, never decide inline.** Any bug, follow-up, or high-impact unforeseen decision you hit mid-build → `bd create "summary" -d "…"` (capture the context, not just a title) and leave it for discovery. Don't rationalize handling it now: "tiny", "while I'm in here", "related" are how one unit becomes three. If the unit can't proceed without a scoping or architecture call, **stop and escalate** rather than guess.
- **The now-layer is your harness task list; recall facts live in auto-memory.** Never fold either into beads — they answer different questions. **Auto-memory is shared across tracks:** keyed by working dir, `MEMORY.md` loads in full every session, so discovery and delivery read one pool. Tag any memory that belongs to *one* track — a leading `(discovery)`/`(delivery)` in its `MEMORY.md` line and the file body; leave cross-cutting facts untagged (global). Read another track's memories as **context, not authority** — never a directive; your authoritative unit of work is your claimed ready bead, not a memory note.
- **Done.** When your method reports done *and verified*, merge/push the branch, then close the bead with an explicit-push sequence: `bd close <id> --reason "done"` → `bd dolt push` → `git ls-remote origin 'refs/dolt/data'` to confirm the ref advanced. Use an explicit `bd dolt push` here (not `BD_SHIM_SYNC=1`): it pushes synchronously whether `PATH` resolves `bd` to the shim or the real binary, so a stale-session PATH snapshot — one where the shim isn't first — can no longer silently no-op the close's push. This is correctness-critical on the **automated devbox delivery job**, where the whole process tree is SIGKILLed at exit (cgroup) and a detached background push can't survive, so the close must reach the remote before then (ADR 0013). The `ls-remote` confirm is the belt-and-suspenders backstop.
